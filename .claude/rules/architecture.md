# Архитектура и границы модулей

- Зависимости направлены внутрь: адаптеры (mcp, rest, telegram, storage) → application → domain. `domain` не зависит ни от чего инфраструктурного (нет Ktor, БД, Telegram, сериализации).
- **agent не ходит в БД core напрямую** — только через MCP (инструменты LLM) и internal REST (системные вызовы).
- MCP-инструмент = то, что может вызвать модель. Системные операции (пользователи, доступ, инвайты, usage, квоты) — **только REST**, никогда не MCP.
- Новый домен (заметки, задачи…) = новый пакет/модуль в core + свои application-сервисы + адаптеры. Не смешивать с напоминаниями.
- Внешние зависимости — за интерфейсами (порты): `Notifier`, `Clock`, `LlmClient`, репозитории. В тестах — фейки.
- Время: всегда через инжектируемый `Clock`, никаких `Instant.now()` / `LocalDateTime.now()` в логике.
- Конфиг — из env/файла, валидируется при старте; приложение падает сразу при некорректном конфиге.
