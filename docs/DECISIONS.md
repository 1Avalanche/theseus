# Theseus — журнал решений

Статус: проектирование, v1 = напоминания. Схемы БД и контракты — ещё не зафиксированы.

## 0. Название и язык
- Проект/платформа — **Theseus** (корабль из «Ложной слепоты»): репозиторий, сервисы `theseus-core`, `theseus-agent`, пакеты `…theseus`. Персона агента — **Сири**.
- Всё, кроме кода, — на русском: документация (`docs/`), KDoc, правила и скиллы Claude, промпты LLM, тексты для пользователя, описания PR. Идентификаторы — английский.
- Сообщения коммитов — **на английском**, формат `<scope>: <summary>` с указанием модуля/функционала (заменяет прежнее «коммиты на русском»).
- Документация обязательна и обновляется вместе с кодом.
- Правила и скиллы, выявленные в работе, сразу добавляются в `.claude/rules` / `.claude/skills`.
- Поиск по коду для Claude — через MCP-сервер индекса IDE (плагин IntelliJ), grep — запасной вариант.

## 1. Платформа и инфраструктура
- Язык: Kotlin. Один репозиторий, многомодульный Gradle. Юнит-тесты обязательны.
- VPS, Docker Compose, `restart: unless-stopped` + healthcheck.
- БД: PostgreSQL. Миграции — Flyway; перед миграцией — автодамп; изменения схемы аддитивные.
- LLM: OpenRouter (OpenAI-совместимый API, tool calling).
- Telegram: long polling (без webhook/домена/TLS).
- Масштаб: до 30 пользователей.

## 2. Архитектура
- Два сервиса:
  - **core** — домен, БД, планировщик, уведомления.
  - **agent** — Telegram-бот + LLM-пайплайн.
- core — гибрид:
  - **MCP** — только инструменты, видимые LLM (операции над напоминаниями и т.п.).
  - **REST (internal)** — системные вызовы агента (пользователи, доступ, инвайты, usage, квоты) и будущие не-ИИ клиенты.
  - Оба — тонкие адаптеры над общими application-сервисами.
- Контекст пользователя: агент передаёт `userId` + сервисный токен в заголовке/`_meta`, **никогда** через аргументы LLM.
- Планировщик — в core, корутина, опрос БД каждые 30–60 с; статус `PENDING → SENT`; при старте — досыл просроченных.
- Уведомления: интерфейс `Notifier` в core; v1 — `TelegramNotifier` (Bot API `sendMessage`).
- История диалога — в отдельной схеме агента в том же Postgres (миграции агента — свои).

## 3. Принцип
- **Всё, что можно сделать детерминированно (код, скрипты, пайплайны), делается кодом.**
- LLM: понимание естественного языка, извлечение сущностей, уточняющие вопросы, семантическое сопоставление, диалог.
- Код: даты/таймзоны/RRULE, валидация, кандидаты на дубли, рендер списков, онбординг, кнопки, snooze, права.

## 4. Доступ и пользователи
- Пользователь = Telegram chatId.
- Админ — chatId из конфига. Команды админа в боте: `/invite`, `/users`, `/revoke`, `/stats`.
- Инвайт: одноразовый код + TTL (~72 ч), ссылка `t.me/<bot>?start=<код>`; при активации — уведомление админу. **Без** подтверждения кнопкой.
- **При генерации инвайта админ указывает грамматический род пользователя** (м / ж / не указан). Не указан → агент избегает гендерно окрашенных форм. Менять позже — через профиль.
- Незарегистрированные chatId отсекаются без вызова LLM.
- Онбординг — детерминированный FSM: имя (кнопка с `first_name` или текст) → таймзона. Без онбординга агент не работает.
- Таймзоны по умолчанию (кнопки): **Москва, Екатеринбург, Другая** (геолокация или город → IANA, с подтверждением). Список — в конфиге.
- Хранение: таймзона — IANA-строка в профиле; время — `timestamptz` (UTC).

## 5. Учёт и квоты
- core хранит usage по каждому LLM-запросу (модель, токены in/out, стоимость из ответа OpenRouter).
- Квоты закладываются в модель данных и API, **в v1 выключены**.

## 6. Агент
- Пайплайн с швом под роутер-классификатор; **v1 — один агент с инструментами** (классификация и уточнения — внутри него). Роутер подключается с появлением второго домена.
- Мягкость: низкая уверенность → уточняющий вопрос; не по теме → вежливо + что умею; жёсткий отказ — только злоупотребление/квота.
- Диалог:
  - последние ~20 сообщений + скользящее саммари; новая «сессия» после паузы в несколько часов;
  - результаты инструментов в истории (сжато);
  - нумерация пунктов списков → `номер → reminderId` в состоянии сессии;
  - связь `telegram message_id → reminderId` (reply на уведомление);
  - `typing`, inline-кнопки для подтверждений, сериализация обработки по chatId.

## 7. Напоминания — сценарии
1. Создать (разовое / повторяющееся), проверка дублей в core → `possible_duplicate` → подтверждение → `force`.
2. Изменить / перенести (для серии: одно срабатывание или вся серия).
3. Удалить (подтверждение; для серии: одно или вся серия).
4. Показать все активные / за период (рендер кодом, нумерация).
5. Найти (core отдаёт кандидатов, LLM сопоставляет по смыслу; позже — pgvector).
6. Snooze с уведомления (+15 мин / +1 ч / завтра), без LLM.
7. Пропустить одно срабатывание серии.
8. Пауза / возобновление серии (в т.ч. «до даты») — **в v1**.
- Повторы: RRULE (RFC 5545) + IANA-таймзона + локальное время; следующее срабатывание считается библиотекой в локальной таймзоне. LLM заполняет структуру (freq, interval, byDay, time, until), RRULE собирает код.
- Время без указания часа → дефолт (напр. 09:00, конфиг).

## 8. Персона «Сири»
- Имя Сири, мужской род («я поставил»), общение на «ты».
- Прототип — Сири Китон («Ложная слепота», П. Уоттс). Берём наблюдательность, точность, сдержанную иронию; не берём холодность.
- Факты о себе — **только из карточки персонажа** (файл, составляет владелец); вне карточки — уклоняется в образе.
- **Спойлеры: говорит только о себе, финал не раскрывает.**
- Образ меняет тон, не поведение: функция важнее образа.
- Детерминированные ответы (онбординг, подтверждения, уведомления) — шаблоны в голосе Сири, в ресурсах.
- Карточка — короткая (~300–500 токенов), отдельный версионируемый файл; промпт собирается из блоков.

## 9. Выбор LLM
- Модель — параметр конфига (по ролям: `main`, `summary`, позже `router`); агент не завязан на провайдера.
- Критерии: русский язык, надёжный tool calling / structured output, низкая латентность, prompt caching. Без reasoning/thinking-моделей.
- В конфиге все три модели, порядок = приоритет (OpenRouter `models` fallback):
  1. `anthropic/claude-haiku-5.5` — **основная** (0.10/0.50 $/1M на 2026-11-02, перепроверить — похоже на промо);
  2. `google/gemini-3.1-flash-lite` (0.25/1.50);
  3. `openai/gpt-5.4-nano` (0.20/1.25).
- summary: самая дешёвая адекватная модель из списка.
- Eval-набор (50–100 русских запросов, детерминированная проверка аргументов tool calls) — подтверждает выбор и служит регрессией при смене модели/промпта.
- Приватность: в OpenRouter ограничить провайдеров / запретить data collection.
- Ответ после успешного tool call — шаблоном (кодом), второй вызов LLM только когда нужен диалог.
