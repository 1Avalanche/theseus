# Хуки Claude Code

Настройка: `.claude/settings.json`. Скрипты: `.claude/hooks/`. Нужен `python3` (3.9+), внешних зависимостей нет.

## bash_guard — защита команд Bash

`PreToolUse`-хук на инструмент `Bash`. Если команда нарушает правила, хук возвращает `permissionDecision: deny` с причиной, и Claude видит, почему команда не выполнена.

### Что блокируется

| Категория | Примеры |
|---|---|
| Рекурсивное удаление вне `build/`, `.gradle/`, `.kotlin/`, `out/` и временных каталогов | `rm -rf src`, `rm -rf *`, `rm -rf /tmp/*`, `find -delete`, `find -exec rm`, `xargs rm -rf` |
| Git, теряющий данные | `reset --hard`, `push --force` / `+ref` / `--delete`, `clean -f`, `checkout .` / `-- путь`, `restore` рабочей копии, `branch -D`, `stash drop/clear`, `filter-branch` |
| Данные БД и Docker | `docker compose down -v`, `docker volume rm/prune`, `docker system prune`, `psql -c "DROP/TRUNCATE …"`, `dropdb`, `flyway clean`, `./gradlew flywayClean` |
| Система | `sudo`, `dd of=…`, `mkfs`, `diskutil erase…`, `shutdown`, `kill -9 -1`, `crontab -r` |
| Внешние процессы Claude | `claude …`, `npx @anthropic-ai/claude-code`, `pnpm dlx …`, `node …/claude-code/…` |
| Запись в файлы проекта через shell | `>`, `>>`, `>|`, `&>`, `tee`, `sed -i`, `perl -i` — кроме `build/`-каталогов, `/dev/null` и путей вне проекта |

Файлы проекта Claude меняет только через Edit/Write: так правки видны в диффе и проходят через разрешения.

### Как разбирается команда

Лексер, близкий к bash:
- учитывает одинарные и двойные кавычки, `$'…'`, экранирование, комментарии;
- **вырезает тела heredoc** — текст внутри них считается данными;
- поэтому `grep "rm -rf"`, `echo 'claude -p'`, сообщение коммита или документ с опасной командой **не блокируются**;
- снятие кавычек не обходит проверку: `r'm' -rf`, `"rm" -rf`, `\rm -rf` распознаются как `rm`.

Рекурсивно проверяется всё, что shell действительно исполнит: `$(…)`, `` `…` ``, `<(…)`, `bash -c '…'`, `eval`, тело heredoc или here-string, переданное `bash`/`sh`, раскрытия `$(…)` в heredoc без кавычек, команды после обёрток (`env`, `timeout`, `nohup`, `xargs`, `nice`, `find -exec`).

Пути: переменные окружения раскрываются (`$TMPDIR`, `$HOME`). Переменная, которой команда сама присваивает значение, считается неизвестной. Неизвестный путь записи считается файлом проекта. `cd` учитывается консервативно: относительный путь проверяется и от старого, и от нового каталога.

**Fail-closed:** неразбираемая команда (незакрытая кавычка, скобка) и внутренняя ошибка хука → блокировка.

### Ограничения (осознанные)

- Содержимое запускаемых файлов-скриптов (`bash script.sh`, `python x.py`) не проверяется.
- `cat file | bash`, `curl … | sh` — то, что приходит в shell через конвейер, не анализируется.
- Запись в файлы из интерпретаторов (`python -c "open(…, 'w')"`) и через `cp`/`mv`/`rsync` не блокируется.
- `case … in` с непарными `)` внутри `$(…)` может не разобраться → команда будет заблокирована (fail-closed).

Хук — страховка от ошибок агента, а не песочница. Полную изоляцию дают права ОС и контейнер.

## doc_guard — сверка документации

`Stop`-хук. Когда агент заканчивает ход, хук смотрит `git status` (включая неотслеживаемые файлы) и сопоставляет изменённые файлы документам по таблице `RULES` в скрипте:

| Изменено | Сверить |
|---|---|
| `src/main/**/*.kt` модуля | `docs/modules/<модуль>.md` |
| `…/mcp/*.kt` | `docs/api/mcp.md` |
| `…/rest/*.kt` | `docs/api/rest.md` |
| `db/migration/**` | `docs/operations.md`, `docs/modules/<модуль>.md` |
| `resources/persona/**` | `docs/persona.md` |
| `resources/prompts/**` | `docs/modules/<модуль>.md` |
| compose, `Dockerfile`, `.env.example`, `application*` | `docs/operations.md` |
| `settings.gradle.kts`, `libs.versions.toml`, `build-logic/` | `docs/architecture.md` |
| `.claude/hooks/**`, `.claude/settings.json` | `docs/claude-hooks.md` |

Не требуют документации: тесты, сами документы, README, `CLAUDE.md`, `.claude/rules|agents|skills`, `.idea/`. У корня проекта и `build-logic/` нет своего `docs/modules/<модуль>.md` (`NO_MODULE_DOCS`): сборка описана в `docs/architecture.md`.

Если есть такие изменения, хук не даёт завершить ход и просит агента: вызвать субагента **docs-writer**, самому дописать `docs/DECISIONS.md`, если было архитектурное решение, или сказать владельцу, что документация уже актуальна.

Защита от надоедания и зацикливания:
- **один раз на набор изменений** — отпечаток содержимого изменённых файлов хранится в `.git/claude-doc-guard.json`; пока код не изменился снова, хук молчит (в том числе в следующих сессиях);
- при `stop_hook_active` (ход уже продолжен Stop-хуком) не блокирует;
- не блокирует, если все предложенные документы уже изменены.

**Fail-open:** ошибка хука не мешает завершить ход (в отличие от bash_guard — это напоминание, а не защита).

Хук не проверяет *качество* правок — только то, что сверка была предложена. Сопоставление путей — эвристика: новый тип файлов добавляется строкой в `RULES` вместе с тестом.

## test_guard — зелёная сборка перед завершением хода

`Stop`-хук. Если код изменился с последнего зелёного прогона, запускает `./gradlew check --continue` (юнит-тесты, ktlint, detekt). Упало — ход не завершается, агент получает выжимку: ошибки компиляции, упавшие тесты и задачи, замечания линтеров, «What went wrong» (до 60 строк).

- **Когда запускается.** По отпечатку содержимого кодовых файлов (`*.kt`, `*.kts`, `*.toml`, `*.sql`, `gradle.properties`; отслеживаемые и новые, без игнорируемых git), а не по `git status` — поэтому проверка не теряется, если агент закоммитил изменения внутри хода. Отпечаток последнего зелёного прогона — в `.git/claude-test-guard.json`. Правка только документов Gradle не запускает.
- **Против зацикливания.** При `stop_hook_active` повторное падение не блокирует, а показывает владельцу предупреждение (`systemMessage`).
- **Fail-open.** Ошибка самого хука ход не блокирует.
- **Время.** Таймаут 600 с. Благодаря кэшу сборки и configuration cache повторные прогоны занимают секунды; первый после изменения build-logic — дольше.
- **Что не входит.** Интеграционные тесты (Testcontainers) и eval-набор LLM в `check` не включаются — это отдельные задачи (правило `testing.md`).

## Субагент docs-writer

`.claude/agents/docs-writer.md`. Получает список изменённых файлов и бриф «что и зачем», читает дифф и документы, обновляет `docs/` и README модулей. Модель — `sonnet`.

Разделение ответственности:
- **docs-writer** — описательная документация: модули, API, эксплуатация, хуки. Только факты из кода и брифа.
- **основной агент** — `docs/DECISIONS.md`: причины решений есть только в его контексте и в разговоре с владельцем.

## Тесты

```bash
python3 -m unittest discover -s .claude/hooks/tests
```

Новое правило блокировки в bash_guard добавляется вместе с тестами: и на блокировку, и на то, что упоминание в строке остаётся разрешённым. Новое правило в `RULES` doc_guard — с тестом на `classify`.
